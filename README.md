# ServiceNow CMDB Health Check

A small Python tool that checks ServiceNow CMDB exports for the problems that make CMDB data hard to trust: duplicate CIs, stale Discovery data, missing required fields, orphaned CIs, broken relationships, and application services with no infrastructure behind them (a CSDM gap).

> **Portfolio project.** Written from scratch for this repository. All sample data is synthetic and generated by `data/generate_sample.py`. No employer or client data, configuration or code is included.

## Why

Incident routing, change impact analysis and Service Mapping all depend on CMDB quality. This tool gives a quick, repeatable health score you can run on a nightly export, before a bulk import, or in a CI pipeline, and it produces a findings file a CMDB admin can work through.

## Checks

| Check | Severity | What it finds |
|---|---|---|
| `duplicate_ci` | high | Same serial number (normalized), or same normalized name within the same CI class |
| `dangling_relationship` | high | `cmdb_rel_ci` rows pointing to a CI that is not in the export |
| `missing_required_fields` | medium | Missing `sys_id`, `name`, `sys_class_name` or `operational_status` |
| `stale_ci` | medium | Operational, discovered CIs not seen by Discovery in N days (default 30) |
| `csdm_service_without_infra` | medium | Application services with no dependency on a server, database or app-server CI |
| `orphan_ci` | low | Infrastructure or service CIs with no relationships at all |

**Health score** = 100 − (weighted findings per CI × 20), floored at 0. Weights: high 3, medium 2, low 1.

## Quick start

```bash
pip install -r requirements-dev.txt      # only pytest; the tool itself uses the standard library
python -m cmdb_health.cli \
  --cis data/sample_cmdb_ci.csv \
  --rels data/sample_cmdb_rel_ci.csv \
  --as-of 2026-11-20 \
  --out findings.csv
```

Sample output (see `sample_output.txt`):

```
CIs checked: 129
Health score: 98.0 / 100
  csdm_service_without_infra       1
  dangling_relationship            1
  duplicate_ci                     1
  missing_required_fields          1
  orphan_ci                        1
  stale_ci                         1
```

Use `--fail-under 95` to make a pipeline fail when quality drops.

### Docker

```bash
docker build -t cmdb-health .
docker run --rm cmdb-health
```

## Exporting from ServiceNow

1. In a personal developer instance, open `cmdb_ci_server.list` (or another class) and export CSV with columns `sys_id, name, sys_class_name, serial_number, operational_status, discovery_source, last_discovered`.
2. Export `cmdb_rel_ci.list` with `sys_id, parent, child, type` (use sys_id values, not display values).
3. Run the CLI on both files.

## Tests

```bash
python -m pytest -q
```

Tests cover each check, edge cases such as unparseable dates, the seeded problems in the sample data, and CLI exit codes. GitHub Actions runs them on every push.

## Security and data handling

- Reads local CSV files only; makes no network calls and needs no credentials.
- Real CMDB exports can contain hostnames and IP addresses. Keep them out of version control (`.gitignore` excludes `findings*.csv`).

## Limitations and next steps

- Duplicate detection is rule-based; ServiceNow's Identification and Reconciliation Engine (IRE) remains the source of truth inside the platform.
- Next: read directly from the Table API with OAuth, add CI-class-specific required fields, and export results to a ServiceNow dashboard.
